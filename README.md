# SecBot 🔐

**SecBot** — Telegram-бот для базовой цифровой гигиены: генерация надёжных паролей, проверка паролей и email на утечки, оценка стойкости паролей и работа с криптографическими хешами.

> Telegram: [@s3cubot](https://t.me/s3cubot)

---

## ✨ Возможности

### 🔑 Генерация паролей

Интерактивный генератор с настройкой параметров:

* длина: **8 / 12 / 16 / 24 / 32** символа;
* пользовательская длина;
* буквы;
* цифры;
* специальные символы;
* исключение визуально похожих символов.

Все параметры настраиваются через **inline-клавиатуру Telegram**.

### 🛡️ Проверка пароля на утечки

Проверка выполняется через **Pwned Passwords API** с использованием подхода **k-anonymity**.

Полный пароль не отправляется на внешний сервер. На сервер передаётся только префикс SHA-1 хеша, после чего совпадение проверяется локально.

### 📊 Оценка стойкости

Для пароля рассчитывается приблизительная **энтропия в битах**, позволяющая оценить количество возможных комбинаций.

### 📧 Проверка email

Email проверяется на наличие в известных базах утечек через **XposedOrNot API**.

### #️⃣ Хеширование

Команда `/hash` позволяет получить:

* MD5;
* SHA-1;
* SHA-256.

### 🧹 Автоудаление паролей

После обработки бот автоматически удаляет сообщение пользователя, содержащее пароль.

> Это уменьшает время нахождения пароля в истории чата, но не гарантирует, что сообщение никогда не было обработано или сохранено инфраструктурой Telegram.

### 🚦 Rate limiting

Middleware ограничивает частоту запросов от одного пользователя, защищая бота от спама и чрезмерного использования внешних API.

## 🚀 Запуск

### Вариант 1 — локально

#### 1. Клонирование

```bash
git clone https://github.com/ApathyIsDead/SecBot.git
cd SecBot
```

#### 2. Создание виртуального окружения

**Windows:**

```powershell
python -m venv venv
venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv venv
source venv/bin/activate
```

#### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

#### 4. Настройка переменных окружения

Создай `.env` на основе `.env.example`:

```text
BOT_TOKEN=your_bot_token
```

`BOT_TOKEN` можно получить через [@BotFather](https://t.me/BotFather).

> ⚠️ Не добавляй `.env` в Git. Файл с токеном должен оставаться локальным.

#### 5. Запуск

```bash
python main.py
```

## 🐳 Запуск через Docker

SecBot также можно запускать в контейнере Docker без установки Python и зависимостей на хост-системе.

### Требования

Установленный **Docker**.

### 1. Создай `.env`

В корне проекта:

```text
BOT_TOKEN=your_bot_token
```

### 2. Собери Docker image

```bash
docker build -t secbot .
```

### 3. Запусти контейнер

```bash
docker run --env-file .env secbot
```

Токен передаётся контейнеру через `.env` и **не включается в Docker image**.

### Остановка

Посмотреть запущенные контейнеры:

```bash
docker ps
```

Остановить контейнер:

```bash
docker stop <container_id>
```

## 🔒 Security considerations

### k-anonymity

При проверке пароля через Pwned Passwords API:

```text
Пароль
   ↓
SHA-1
   ↓
Первые 5 символов ─────→ API
                         ↓
                   список суффиксов
                         ↓
                  локальное сравнение
```

Таким образом, полный пароль и полный SHA-1 хеш не передаются внешнему API.

### Отсутствие хранения паролей

SecBot не сохраняет введённые пользователем пароли в базе данных и не записывает их в логи в открытом виде.

### Удаление сообщений

Сообщение с введённым паролем удаляется после обработки.

Это снижает риск случайного раскрытия пароля в истории Telegram-чата, но не является абсолютной гарантией конфиденциальности: сообщение сначала поступает в Telegram и обрабатывается ботом.

### Внешние API

Для проверки данных используются:

* **Pwned Passwords API** — проверка паролей;
* **XposedOrNot API** — проверка email.

Внешние API используются только там, где это необходимо для соответствующей проверки.

### Rate limiting

Ограничение частоты запросов предотвращает:

* спам командами;
* чрезмерное количество API-запросов;
* ненужное расходование лимитов внешних сервисов.
