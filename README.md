# SecBot 🔐

Telegram-бот для базовой цифровой гигиены: генерация надёжных паролей, проверка паролей на утечки и проверка email на присутствие в известных базах утечек.

> В Telegram бот доступен как [@s3cubot](https://t.me/s3cubot) (юзернейм такой, потому что нормальные варианты с "sec"/"secbot" были заняты).

## Зачем это

Большинство людей всё ещё используют слабые или повторяющиеся пароли и не знают, что их данные могли утекнуть. SecBot даёт быстрый способ проверить это прямо в Telegram, не открывая сомнительные сайты и не вводя пароль на сторонних сервисах напрямую.

## Возможности

- **Генерация паролей** — выбор длины через пресеты (8/12/16/24/32) или свою длину, плюс переключатели наборов символов (буквы/цифры/спецсимволы/исключение похожих символов) через inline-клавиатуру
- **Проверка пароля на утечку** — через k-anonymity подход (Pwned Passwords API): полный пароль или его хеш никогда не покидает устройство пользователя в открытом виде
- **Оценка стойкости пароля** — на основе расчёта энтропии (в битах)
- **Проверка email на утечки** — через XposedOrNot API
- **Хеширование текста** — MD5, SHA-1, SHA-256 по команде
- **Автоудаление сообщений с паролем** — бот сам удаляет сообщение с введённым паролем из чата после обработки (для email пока не реализовано)

## Команды

| Команда | Описание |
|---|---|
| `/start` | Приветствие и список возможностей |
| `/password` | Сгенерировать пароль (интерактивно, через кнопки) |
| `/hash <текст>` | Показать хеши текста (MD5, SHA-1, SHA-256) |
| `/check` | Проверить пароль или почту на утечку — бот спросит, что именно проверить |

## Установка и запуск

```bash
git clone https://github.com/<твой_юзернейм>/secbot.git
cd secbot

python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# впиши свой BOT_TOKEN в .env, полученный у @BotFather

python main.py
```

## Security considerations

- **k-anonymity вместо полного хеша.** При проверке пароля отправляются не сам пароль и не полный SHA-1 хеш, а только первые 5 символов хеша — сервер возвращает список суффиксов, совпадение ищется локально. Это стандартный подход к проверке паролей на утечки.
- **Удаление сообщения с паролем.** Бот удаляет сообщение пользователя с введённым паролем сразу после обработки, чтобы оно не висело в истории чата. Ограничение: Telegram всё равно хранит сообщение на своих серверах некоторое время до фактического удаления — это снижает риск, но не устраняет его полностью. Для email такого удаления пока нет (см. Roadmap).
- **Источники данных об утечках.** Рассматривались несколько вариантов (HIBP, XposedOrNot, DLBI, chk.safe-surf.ru). Выбран XposedOrNot как сервис с открытым и бесплатным API, документированным для сторонних интеграций.
- **Не хранит и не логирует пароли.** Пароли и введённые данные не сохраняются в базу и не пишутся в логи в открытом виде.
- **Rate-limiting.** Middleware ограничивает частоту сообщений и нажатий на кнопки от одного пользователя — защита от спама командами и от исчерпания лимитов внешних API (Pwned Passwords, XposedOrNot) при массовых запросах.
